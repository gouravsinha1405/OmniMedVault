OmniMedVault in a working browser UI

This page sits directly on top of the current backend. It lets you request demo OTPs, sign in as a patient or doctor, update the patient profile, upload documents, manage consent, inspect audit logs, and view doctor-facing patient access.

Demo-first workflow

Debug OTPs are surfaced here so you can move quickly without wiring SMS first.

1. Session

Start with OTP request and verify. Patient and doctor demo flows are both supported.

2. Live Response Console

Every action writes the latest request result here so you can inspect the live payloads.

Ready.

3. Patient Profile

Use a patient session to read and update the self profile.

4. Patient Documents

Upload a file as multipart form data, then list the stored document metadata.

5. Patient Consent

Grant a doctor access, then revoke it. Switch to a doctor session to see the doctor list update.

6. Doctor View

Use a doctor session and the current phone number to load the consented patient list.

7. Audit Trail

This shows the append-only audit events generated by the current patient session.
